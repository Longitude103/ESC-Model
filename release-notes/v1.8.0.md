## Result changes since v1.7.0

**Natural vegetation recharge is split by NRD by area.** Before, every model cell sent all of its natural vegetation recharge to one NRD file type (126 North Platte, 127 South Platte, 102 outside both), picked from whichever zone record came last, so cells on an NRD boundary landed in an arbitrary NRD. Each cell's natural vegetation area is now split by how much of the cell lies in each NRD. In Post-97 and Total Depletion runs, land freed up by a removed parcel is filed under that parcel's NRD. Steady state uses the same split.
*What to expect:* cell totals are unchanged. Recharge moves between file types 126, 127 and 102 along the NRD boundaries, so NRD-level natural vegetation totals shift.

**South Platte NRD pumping in 2009 and earlier is estimated for every parcel.** 2009 was a transition year with metered and unmetered wells mixed inside each subarea. A logic error treated every SP parcel with a subarea as metered in 2009, so unmetered parcels got zero pumping unless they had reported usage. All SP parcels are now estimated through 2009, and certificates with reported usage still use the reported meter amounts.
*What to expect:* SP NRD pumping (WEL) in 2009 goes up, along with the irrigation recharge that comes with it. Other years and the North Platte NRD are unchanged. Runs no longer crash on SP subareas shorter than 3 characters.

**Irrigated pasture (crop 12) uses dryland pasture for its dryland ET.** CropSim has pasture only as irrigated pasture (12) and dryland pasture (13). The ET gain step looked up dryland ET for crop 12, found none and used zero, so all pasture ET counted as gain from irrigation.
*What to expect:* irrigated pasture parcels count less of their applied water as consumed, so more of it returns as runoff and deep percolation, which raises irrigation recharge on those parcels. Pumping is unchanged.

**Steady-state dryland fallow keeps its fallow crop.** Steady-state dryland parcels with fallow (15) were changed to irrigated pasture (12), which has no dryland CropSim data, so they produced no runoff or deep percolation.
*What to expect:* steady-state dryland recharge (file types 128, 129 and 101) goes up where there is fallow. Transient runs already did this correctly.

## The run now stops on pasture crop code errors

These parcels used to run silently with zero water. The run now stops and lists every bad parcel with its parcel number, NRD, year, certificate, model id, subarea, irrigation type, acres and crop slot, so they can be fixed in the database:

- An **irrigated** parcel coded as pasture (13). It got no NIR and no pumping. Change it to irrigated pasture (12).
- A **dryland** parcel coded as irrigated pasture (12). It got no runoff or deep percolation. Change it to pasture (13).

If your run stops with one of these messages, fix the crop codes for the parcels listed and run again.

## Upgrading from v1.6.x

v1.7.0 was published without download files, so if you are moving from a v1.6 build you also get the v1.7.0 changes. The main result changes there were:

- Recharge on parcels with more than one soil now counts every soil, and surface water delivery is no longer counted once per soil (larger irrigation recharge, smaller SW delivery on multi-soil parcels).
- Runoff now reaches recharge for natural vegetation and dryland (it was always zero).
- Unmetered pumping is estimated as gross water applied, (NIR − SW × efficiency) / application efficiency, instead of net NIR, so estimated pumping goes up.
- Mitchell canal delivery after 1984 now includes the day-cfs to acre-feet factor (about double before) and no longer drops to zero in months without a Gering record.
- Excess flow canal recharge is no longer double counted when two periods fall in one month.
- The first CropSim record (1953) is no longer skipped, and steady-state annual stress periods use the right number of days.
- Dryland recharge is written as 128 NP / 129 SP, steady-state natural vegetation as 126 / 127, and Total Depletion runs leave out municipal and industrial pumping.
- `mfFiles` asks for a file name suffix and header description, and each WEL file gets its own flow-reduction CSV.

The full list is in the [v1.7.0 release](https://github.com/Longitude103/ESC-Model/releases/tag/v1.7.0).
